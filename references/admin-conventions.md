# 管理后台 PRD 写作规范（专属）

> 仅用于判定为「管理后台 / 运营后台 / ERP 类内部系统」的原型。客户端原型不要用本文件，改用 `writing-rules.md + sample-prd.md`。
> 判定特征：顶部筛选/查询条件、字段密集列表、状态机、二次确认、批量操作、导出、操作日志、分域/数据权限、erp 取数分支。

## 一、标准模块结构（按此顺序组织一个后台模块）

1. **查询** —— 筛选条件 + 模糊查询 + 条件联动 + 默认全部
2. **列表字段** —— 逐字段写展示内容 / 取值来源 / 格式 / 生成规则
3. **创建** —— 取数说明 + 设置弹窗 + 字段校验 + 保存拦截与 toast
4. **详情** —— 分开展示 + 查询 + 字段 + 状态机 + 操作 + 批量 + 操作日志 + 导出 + 分域
5. **编辑** —— 可编辑 / 不可编辑范围、删除是否直接生效
6. **删除** —— 二次确认
7. **设置** —— 数据来源、权限
8. **操作日志** —— 查询 + 事件枚举 + 操作对象 + 操作人 + 时间
9. **分域 / 数据权限** —— 总部 / 门店可见范围、品类 / 门店权限

多张截图若是同一模块的「列表页 / 创建弹窗 / 详情页 / 编辑页」，合并进同一份 PRD 的对应模块，不要拆成多份。

## 二、后台专属必写规则

- **查询条件**：下拉单选、输入模糊查询、条件间联动（如筛选了总部/门店，则组织名称仅限该范围）、默认筛选全部；字段格式写明（年月日时分秒 / 流水码规则如 `XPSX+日期+流水码`）。
- **列表字段**：每个字段写清「展示什么 + 取值来源（系统生成 / 后台字段 / erp）+ 格式」。复合展示（如「公司简称-部门名称-部门名称」）要写清拼接规则与层级；同一对象在不同维度分开展示时（如同商品不同门店）要说明拆分规则。
- **排序**：变更时间倒序——无操作时间按创建时间，有操作时间按操作时间。
- **二次确认**：删除、转正、下架、批量操作必须二次确认，给出确认弹窗文案原文。
- **状态机**：列出全部状态及触发流转（如 进行中 → 已转正 / 已延期 / 已下架）；终态（已转正 / 已下架）后不可再操作；延期可继续延期；转正仅做标记不实际改 erp 状态（除非明确说明）；下架是否同步改 erp 状态要写清。
- **批量操作**：可多选；部分不可操作时只操作可操作的；二次确认弹窗中展示「可操作数量」。
- **分域 / 数据权限**：总部岗位可见范围、门店岗位可见范围、品类 / 门店权限；「只要试销单含该岗位品类即可查看整单」类规则要写清。
- **操作日志**：事件枚举（创建 / 编辑 / 删除 / 设置 / 延期 / 转正 / 下架）、操作对象（试销单号 / 商品名，设置类不展示）、操作人、操作时间（年月日时分秒）、可按时间段 / 事件 / 对象 / 人查询。
- **导出**：按列表字段导出；过长数字单元格导出为文本或加 `'`（见 checklist 77）。
- **取数分支**：erp 提供 vs 本系统设置，两种逻辑分别描述（字段来源、默认值、是否可改）。
- **字段校验与 toast**：必填、至少保留一个完整、部分不完整不保存；拦截 toast 原文，变量用 `xxx` 占位、多个用分号分隔（如 `xxx 商品已经是新品，请勿重复设置`）。
- **统计口径**：每日定时（如 2:00）更新；销售额 / 数量需去掉退货；下架 / 转正 / 超期不再统计——写清口径与更新时点。
- **权限细分**：某岗位无某模块权限（如门店无设置权限）；非创建者只能查看 + 操作商品状态，但不可编辑 / 删除整单——写清各角色的编辑/操作边界。

## 三、编号规范（后台与客户端通用）

后台与客户端共用同一套全角编号，无差异：

| 层级 | 符号 | 示例 |
|---|---|---|
| 一级 | `一、` `二、` … | `一、查询` |
| 二级 | `1、` `2、` `3、` | `1、创建组织` |
| 三级 | `（1）` `（2）` `（3）` | `（1）商品编码` `（2）商品名称` |
| 四级 | `①` `②` `③` | `① 字段取值来源` |
| 五级 | `• ` | `• 成员等级校验` |

- 后台**不再使用 `a. b. c.` 字段枚举写法**；列表字段逐字段一律写作 `（1）商品编码` `（2）商品名称`…，选项 / 分支枚举同样用 `（1）（2）`，更深一层用 `①`。
- 全部同全角规范，句读用中文顿号 `、` 和全角括号 `（）`。
- **禁止**使用 Markdown 的有序列表（`1.`）或标题号（`##`）承载正文编号。
- 一级条目行只写模块名，不加冒号。

## 四、与通用 checklist 的关系

`checklist.md` 的要素 / 整体 / 列表 / 特殊 / 场景全部适用。后台额外重点核对：分域（整体 33/44/80）、二次确认、操作日志、批量操作、导出格式、取数分支、字段校验 toast、状态机终态（整体 28/46/66）、跨端刷新（整体 34/35）、重复提交（整体 57）、删除状态设计（整体 59）。
