# foodprd — 原型截图转中文 PRD

> WorkBuddy 技能：把一张或多张原型截图 / 设计稿，转写成可直接交付研发的中文 PRD，**自动套用固定的编号规范与既定写作风格**。

收到原型截图后，技能会**先判断是「客户端」还是「管理后台」**，再读取对应风格样例与编号规范写作，最后对照产品设计注意事项清单逐项自检后交付。

---

## 能做什么

- **客户端 / C 端 / H5 / 小程序 / App 页面**：活动页、资讯流、商详页、表单页、视频 / 图片展示页等。
- **管理后台 / 运营后台 CRUD 模块**：列表页、查询筛选、创建 / 编辑弹窗、详情页、操作日志、分域权限等。
- 多张截图自动区分「同一页面不同状态」（合并分态）与「不同页面」（分节或分文档）。
- 缺信息不来回追问，按合理默认补全并标注 `（待确认）`，一次交出完整文档。

## 核心特性

| 特性 | 说明 |
|---|---|
| 双模式识别 | 先判定前端 / 后台，分别套用不同的风格样例、模块顺序与编号体系 |
| 固定编号规范 | 一级 `一、` 二级 `1、` 三级 `（1）` 四级 `①` 五级 `•`（后台字段枚举用 `a. b. c.`）。禁止用 Markdown 有序列表承载，防渲染变形 |
| 字号排版 | 一级标题 16pt 加粗，其余 14pt 不加粗（导出 docx / HTML 时严格套用） |
| 风格样例 | 内置真实 PRD 样例（客户端活动页 + 后台新品试销单），颗粒度与句式对齐 |
| 产品设计 checklist | 内嵌 80+ 条产品注意事项（要素检验 / 整体检验 / 列表通用 / 特殊注意 / 场景矩阵），交付前逐项自检 |
| 全局排除项 | 顶部导航栏、底部 tab bar 属全局框架，不写入单页 PRD（页面内 tab 仍写） |

## 目录结构

```
foodprd/
├── SKILL.md                      # 技能主文件：流程、编号规范、写作规范
├── README.md                     # 本文件
├── assets/
│   └── prd-skeleton.md           # 客户端空白骨架模板
└── references/
    ├── sample-prd.md             # 客户端权威风格样例（真实活动页 PRD）
    ├── sample-prd-admin.md       # 管理后台权威风格样例（新品试销单 PRD）
    ├── writing-rules.md          # 客户端元素类型 → 必写规则、文案库、状态矩阵
    ├── admin-conventions.md      # 后台模块结构 + 专属必写规则 + 后台编号
    └── checklist.md              # 产品设计注意事项总清单（自检底线）
```

## 编号规范速查

**客户端**

| 层级 | 符号 | 示例 |
|---|---|---|
| 一级 | `一、` `二、` … | `一、页面标题` |
| 二级 | `1、` `2、` `3、` | `1、搜索框` |
| 三级 | `（1）` `（2）` | `（1）参赛作品信息` |
| 四级 | `①` `②` … | `① 参赛编号：展示参赛编号` |
| 五级 | `• ` | `• 会员等级校验` |

**管理后台**

| 层级 | 符号 | 示例 |
|---|---|---|
| 一级 | `一、` `二、` … | `一、查询` |
| 二级 | `1、` `2、` `3、` | `1、创建组织` |
| 三级-字段 | `a.` `b.` `c.` | `a.商品编码` |
| 三级-选项 | `（1）` `（2）` | `（1）全部门店统一设置` |

全部使用全角序号；正文写纯文本行，层级间空行分隔。

## 使用方式

在 WorkBuddy 中加载 `foodprd` 技能后，直接发一张原型截图，并说「写 PRD」即可。技能会：

1. 判定客户端 / 管理后台 → 读取对应样例与规范
2. 读图拆模块（自上而下、从主到次）
3. 按编号规范写作（每元素写齐：取值来源 / 展示规则 / 交互结果）
4. 对照 `checklist.md` 逐项自检，相关项必须交代，写不出标 `（待确认）`
5. 输出到工作区 `output/<页面名>-PRD.md`，需要 Word 再转 docx

## 全局排除项（默认不写入 PRD）

- **顶部导航栏**：返回按钮、页面标题、全局搜索 / 头像 / 更多图标
- **底部 tab bar**：首页 / 发现 / 我的 等全局底部导航

> 例外：页面**内部**的 tab 切换（如 企业动态 / 心声、参赛作品 / 排行榜）属于页面功能，仍要写，但单独成模块，不归入「顶部导航栏」。
