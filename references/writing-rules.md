# 元素必写规则清单 / 通用文案库 / 自检清单

原型只画"长什么样"，PRD 要补的是**什么情况下、怎么运作**——**不重复描述视觉样式**（见 SKILL.md「写作规范（通用）」第 14 条）。下表按元素类型列出**必须写到**的规则点，逐项核对可避免绝大多数需求遗漏。

## 一、按元素类型核对

### 文本类（页面标题、名称、昵称、地址、简介）
- 取值来源：后台设置的「X」字段 / 用户填写的「X」/ 接口返回
- 超长处理：`如果超过固定区域，末尾用“…”表示`（多行则写"最多展示 N 行，超出末尾用“…”表示"）
- 是否需要展示全部文字（长文案区域要显式写"需要展示后台设置的全部文字"）
- 空值兜底：字段为空时展示什么（隐藏该行 / 展示默认文案）

### 图片类（头图、banner、轮播、介绍图、头像）
- 取值来源与**排序规则**（按上传顺序由前往后）
- 是否自动轮播、间隔秒数、是否支持手动切换
- 是否循环（节奏与行为类规则；指示器外观等视觉样式不写）
- 图片适配：写清"是否完整展示 / 是否裁剪"（如 `按原图比例完整展示、不做裁剪`）；宽度撑满、留白处理等视觉适配方式由视觉稿定义，不写入
- 视频取封面：`如果是视频则截取画面第一帧`
- 未上传时的占位规则（加载失败属网络态，见全局排除项）

### 数据指标类（人数、票数、浏览量、销量、金额）
- 统计口径定义（pv 含不含重复访问、含不含游客）
- **删除后是否回退**：报名数/票数需同步减少；pv 类不回退
- 数字格式化：`超过 9999 则单位展示“w”，展示 1 位小数，第二位小数直接舍弃不进位；超过 9999.9w 展示为 9999.9w+`
- 是否需要精确展示（排行榜票数"数字要具体展示出来"，不做缩写）
- 0 值展示

### 倒计时 / 时间提示
- 分状态：未开始算到开始时间，进行中算到结束时间，已结束展示固定文案
- 展示粒度：天、小时、分钟、秒
- `如果数字是个位数需要补零展示`
- 倒计时归零瞬间的状态切换（是否需要自动刷新页面）

### 搜索
- 支持的关键词类型（编号 / 姓名 / 手机号）
- 输入后展示「删除」按钮，点击删除或手动清空恢复未输入状态
- 空关键词点击搜索的 toast 原文
- 结果展示在哪个 tab / 区域、结果排序要求、结果项的信息与交互是否复用列表
- 无结果文案原文
- 是否支持模糊匹配、是否区分大小写（待确认可标注）

### tab
- 默认选中哪个 tab
- 切换是否保留各 tab 的滚动位置与分页状态
- 选中态与未选中态需区分（只写"需区分"，具体样式由视觉稿定义）
- 各 tab 内容分别成一个二级条目

### 列表 / 卡片流
- 每个字段逐一列出（编号、预览、名称、数值、按钮）
- **排序规则**含并列时的次级因子（相同票数按最后一票时间早者靠前；无投票按报名时间早者靠前）
- 各状态下按钮的显隐（见状态矩阵）
- 整卡可点区域：`点击预览区域、姓名区域、票数区域，均跳转 X 页`
- 分页粒度（卡片流常见每 6 个，列表常见每 10 条）
- 到底提示文案
- 空页面状态**不写**（见 SKILL.md 全局排除项）

### 排行榜
- 排名计算规则（同上）、是否展示全部排名
- 头像来源（用户微信头像）
- 未开始但已有数据时是否展示榜单（默认展示，仅隐藏操作按钮）
- 前三名是否需要特殊标识（如名次图标、奖牌）——**只写"是否需要"，不描述标识样式**
- 多个空/未开始文案冲突时的**优先级**

### 说明 / 须知类富文本（活动详情、报名须知、考核说明等长文案区）
- 取值来源：后台配置的富文本/图文内容，需显式写"需要展示后台设置的全部文字，不做截断，超出支持上下滚动"
- 排版能力：是否支持无序列表 / 有序列表 / 正文插图，按后台配置样式展示（字号、字重等视觉细节不写）
- **变量占位**：文案中的 `{{字段名}}` 为后台配置变量，需写清展示时替换为实际数值，并在原型文案收录时保留原始占位写法
- 栏目结构不同时（如不同活动类型的栏目不一致）：列出各类型的栏目名称与固定顺序，取后台配置
- 原型文案原文建议按栏目收录（供后台配置参考），但**规则类条款要写成规则**（如"累计缺勤超过 {{学时数}} 学时须顺延重修"），不要只贴文档

### 得分 / 进度类可视化（得分圆环、进度条、仪表盘、雷达图等）
- 数值来源与口径：取数来源、计算方式（各题得分之和 / 加权 / 是否含未作答）、是否与满分同时展示（如 `12/20`）
- 数值格式：小数位与取整规则、单位（分 / % / 次）
- 是否展示进度填充（有 / 无）属展示规则，可写；"填充多少、什么颜色"属视觉，不写
- **档位规则**：是否按档位区分（及格 / 不及格、达标 / 未达标）、各档的**阈值**，以及阈值取后台配置还是写死；**色值与视觉样式不写**（由视觉稿定义）
- 原型通常只画一种样式（统一灰色、整圈同色、无填充）→ 凡原型未体现档位区分的，一律标 `（待确认）`，**不要臆造配色或进度**
- 若同页还有积分 / 奖励 / 等级等派生结果，写清其计算依据（取后台配置，前端不参与计算）

### 底部悬浮 bar / 主 CTA
- 按钮在各状态下的文案与显隐（我要报名 / 已报名 / 活动已结束）
- 前置校验链与**优先级顺序**：`登录>判断会员等级>触发订阅消息>进入报名页`
- 不满足条件的拦截方式：弹窗还是 toast，文案原文，弹窗按钮的去向
- 已结束态是否可点（`点击无交互`）
- 是否固定展示在页面底部、不随内容滚动（属交互行为，可写；按钮外观不写）

### 弹窗
- 触发时机（进入哪个页面、获得奖励后）
- 频控：只弹 1 次 / 每天 1 次 / 每次进入都弹
- 文案中的变量替换说明（`弹窗文案「」中的内容展示活动名称`）
- 提供的操作及各自去向（跳转对应明细页 / 关闭并停留）
- **弹窗优先级与冲突处理**：谁先弹、被挤掉的弹窗何时补弹、多个同类弹窗的排序与层级

### 页面级状态
- 未开始 / 进行中 / 已结束
- 被删除、已下架（网络异常、弱网、加载中、加载失败等网络态按 SKILL.md 全局排除项默认不写入 PRD）
- 未登录 / 游客可见范围
- 权限不足

### 分享
- 分享渠道、分享卡片标题与图片取值、分享后回流页面
- 已有组件文档时写「详见分享组件页」

### 订阅消息 / 通知
- 触发节点、使用的模板（`需要新增一个中奖通知模版，原有的不适用`）
- 是否支持多次订阅

## 二、通用文案库（直接复用，保持一致性）

| 场景 | 文案 |
|---|---|
| 列表到底 | “已经到底啦～” |
| 搜索无结果 | “暂无搜索结果” |
| 活动结束 | “活动已结束” |
| 未开始-列表 | “活动开始后可进行投票” |
| 未开始-排行榜 | “活动暂未开始，暂无排行” |
| 无内容 | “暂无参赛作品” |
| 搜索空关键词 toast | 请输入编号或者姓名 |
| 会员等级不足 toast | 非常抱歉，该活动仅限 xx、yy 会员参与 |

## 三、状态矩阵模板

不确定某元素在某状态下的表现时，先填这张表，再逐格写进 PRD。

| 元素 | 未开始 | 进行中 | 已结束 |
|---|---|---|---|
| 主 CTA | 我要报名 | 我要报名 / 已报名 | 活动已结束（不可点） |
| 列表操作按钮 | 提醒我 + 提示文案 | 拉票 / 投票 | 查看详情 |
| 倒计时 | 距开始 | 距结束 | 活动已结束 |

## 四、交付前自检清单

- [ ] 编号层级正确：一、/ 1、/（1）/ ① / •，无 Markdown 自动编号
- [ ] **无 UI 层描述**：颜色 / 字号 / 字重（加粗）/ 圆角 / 尺寸 / 对齐 / 底色 / 分隔线 / 图标样式等视觉呈现已全部剔除，只保留产品逻辑规则（见 SKILL.md 写作规范第 14 条）
- [ ] 模块顺序与原型自上而下一致
- [ ] 三态（未开始/进行中/已结束）每个交互元素都交代了显隐
- [ ] 所有文本字段写了超长截断规则
- [ ] 所有数字写了格式化与极值规则、时间写了补零
- [ ] 所有列表写了排序规则（含并列次级因子）、分页粒度、到底文案
- [ ] 数据指标写了统计口径与删除后是否回退
- [ ] 所有跳转写清目标页面
- [ ] 所有 toast / 弹窗给出文案原文
- [ ] 多重校验给出了优先级顺序
- [ ] 弹窗给出触发时机、频控、优先级冲突处理
- [ ] 页面异常态（被删除、已下架）有交代（网络异常 / 弱网 / 加载失败等网络态按全局排除项跳过，不写）
- [ ] 原型中的残留样式与矛盾文案已识别，未照抄成规则，已按合理默认写出并标注（待确认）
- [ ] 得分 / 进度类可视化写了数值口径、档位阈值与是否展示进度，原型未体现的一律标（待确认）
- [ ] 页面拆分正确：每个页面一份独立文档，同一页面多状态在同一份内分述，不同页面（即使同一业务流程）未合并、已用交叉引用串联
- [ ] 推断项已标注（待确认），无空缺、无 TBD 占位段
