# 产品设计注意事项总清单（交付前自检底线）

> 来源：用户积累的产品设计 checklist（含社区条目 https://www.jianshu.com/p/37ec8ce640cf）。
> 用法：写 PRD 时**动笔前先想模块影响**，写完后按本清单逐条自检。凡与本功能相关的条目，PRD 中都必须有明确交代；从原型看不出的规则，按合理默认写出结论并在行尾标 `（待确认）`，禁止留空。

## 前置：模块影响分析

做功能前先考虑：这个功能可能对哪些模块产生影响。

- **逻辑影响**：是否改变既有状态机、统计口径、权限判断、数据刷新链路；是否与其他模块共享同一份数据/同一状态。
- **展示影响**：是否复用既有组件、是否改变全局一致性既有规则（占位图、文案、空/异常态）。

---

## 一、要素检验

1. **边界值**（最长、最短、空）：一定要给最大值。
2. **交互效果**：可不可点击，点击之后怎样。
3. **数据计算复杂度**：是否需后端定时统计、是否影响性能。
4. **数值小数与取整**：若存在数值要素，考虑是否还有小数、如何取整（计算精度）。
5. **小数去尾零**：数值后若存在小数，要去掉 `.00`。

---

## 二、整体检验

1. 空状态
2. 多变量的排序
3. 注意考虑推送
4. 兼容性
5. 数据埋点
6. H5 页面注意分享文案及缩略图、落地页；注意微信环境二次分享的文案、缩略图
7. 先确定是否为原生开发，若否，则右上角不能安排按钮
8. 最底层页面要展示全部信息，不能省略
9. 设计全局一致性
10. 逻辑改变之后，旧数据处理问题
11. 如果是悬浮按钮，考虑做成可拖拽移动的
12. 注意列表类型数据进行分页
13. 争议性功能，一定要在后台做开关
14. 能运营后台配置的一定要进行配置
15. 运营后台尽量先上
16. 上线前 3 天，提醒运营部门准备物料
17. 涉及时间考虑是否包含今日
18. 涉及销量/订单考虑是否为确认收货或其他订单状态，注意看下平台都有哪些订单状态
19. 上线前针对客户可能出现的疑问撰写 FAQ
20. 给相关人员配置权限
21. 性能优化：图片大小、定时统计等
22. 注意运营后台列表的排序
23. 评审会一定写会议纪要，以防业务部门事后反悔
24. 完全按需求去验收，没有模糊地带
25. 运营后台涉及编辑功能，一定要做上下线的功能
26. 产品上线后，如有注意事项，应及时更新到原型中
27. 涉及退款注意部分退款情况
28. 活动结束后需不需要有个结束状态做处理
29. 注意分享的落地页，如果允许用户选择不同页面怎么办
30. 参加活动的商家商品是否允许操作（上下架、编辑），如果否怎么提示
31. 退货会造成什么影响
32. 同一元素能否出现在不同主题
33. 考虑平台不同角色
34. 操作后考虑数据刷新
35. 在不同端操作，另外一端数据刷新问题
36. 写清楚交互
37. 排序序号从 1 开始
38. 导出订单的格式、命名
39. 是否可重复（标题、序号）
40. 提示弹窗弹出频率
41. 注意已下架商品
42. 用户操作路径越短越好
43. 注意给最大值和默认值
44. 注意考虑是否存在多个入口
45. 推送考虑有没有不推送的情况
46. 做状态时注意做结束状态
47. 内容安全：设计 UGC 内容是否需要校验包含敏感词
48. 后台查询数据时，若可直接输入页码，则需考虑数据查询效率问题
49. 发送内容时注意空白、空格内容的发送
50. 写需求时注意写「返回」按钮的交互
51. 后台数据排序，若数据量大，考虑用主键进行排序
52. 回到顶部：考虑回到顶部功能
53. H5 注意考虑 M 站情况
54. 审核状态注意审核中可不可以再更换的问题
55. H5 填写资料时，注意不要跳转新页面去选择
56. 请求权限的描述不可自定义，网络权限不用主动请求
57. 注意提交时处理重复提交的问题
58. 发布商品返回时，不要返回发布页，以免造成商品重复发布
59. 设计表时，注意设计删除状态
60. 对一个对象进行操作时，要对该对象向下分解，分解成最小单位
61. 如果网络断开，点击按钮注意 toast 提示
62. 网络状态：表单提交 toast，进入新页面展示无网络页面；分类——无网络、弱网、飞行模式、认证网络、网络权限
63. 短信文案
64. web 端断点续传的问题
65. 做 App 时，注意写对浏览器的要求
66. 注意不同元素的状态：被删除等
67. 列表页若有详情页，要加箭头提示
68. 如果进入 H5 页面，考虑怎样回到首页的问题
69. 推送影响因素：手机本身有设置
70. 服务端做还是客户端做
71. 重复提交的问题（同 57）
72. 尽量做批量导入的功能
73. 小程序注意分享时考虑分享到朋友圈的缩略图
74. 是否支持换行
75. 是否允许重复（同 39）
76. 页面到底文案
77. 过长数字导出为表格时，单元格格式导出为文本或加 `'`
78. 跨企业的问题
79. 每个营销活动需要单独在微页面做营销组件
80. 后台页面需要有返回按钮

## 三、列表通用需求

1. 是否可分享（分享按钮、分享文案、缩略图；落地页是 H5 还需提醒开发注意二次分享）
2. 排序
3. 分页
4. 加载策略（无网络、加载中、加载失败，一般有全局处理方式）
5. 空状态
6. 交互
7. 列表组成元素的不同状态（如商品考虑不同状态、时间格式怎样）
8. 不同权限状态（无权限的处理）
9. 元素的溢出处理（文案过多、数字过多怎么处理）
10. 列表到底的文案提示
11. 一键到顶按钮

---

## 四、特殊注意事项

1. 藏品类型区分一口价 / 拍卖
2. 注意纯 H5 分享，谨防被封
3. 文字不够展示直接截断即可
4. 占位图不要带「网」字
5. 注意售后包括重启售后情况
6. 推送时考虑是否推送到公众号
7. 注意没人出价时展示起拍价
8. JPush 推送：单标题可走厂商通道，到达率更高；其它走极光通道，App 不在线时下次打开才能收到。厂商通道有限制（如 vivo 一天仅 5 条走厂商通道），其余厂商需确认。
9. 注意配置教程时，测试环境链接与生产环境链接 id 保持一致
10. 头像、昵称注意区分是店铺还是买家

## 五、场景检查矩阵

写功能时按「状态 × 元素」逐一过：网络态、H5 态、同一元素重复出现、其他元素、兼容性。

| 状态＼元素 | 网络 | H5 | 相同元素 | 其他元素 | 兼容 |
|---|---|---|---|---|---|
| 无链接 | 分享文案 | 同时出现 | 类型 |  |  |
| 弱网 | 缩略图 |  | 状态（删除、空） |  |  |
| 代理 |  |  | 数据更换（增删改查） |  |  |
| 服务器错误 |  |  | 大小或长短 |  | 不同的入口 |

凡矩阵中触达的场景，PRD 都要给出对应表现或处理。
